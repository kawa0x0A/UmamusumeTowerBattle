# ウマ娘タワーバトル

「どうぶつタワーバトル」を参考にした、ブラウザで動くターン制の積み上げ対戦ゲームです。
コマになるのは [ウマ娘 プリティーダービー 公式ポータルサイト](https://umamusume.jp/character/)
のキャラクター一覧に掲載されている**立ち絵画像（全身・171体）**で、
**ダウンロードせず URL 参照のまま**表示しています。

---

## 遊びかた

| モード | 内容 |
| --- | --- |
| CPU と対戦 | CPU と交互に積む。ボタンを押すと続けて強さ（かんたん / ふつう / つよい）を選ぶ |
| 2人で対戦 | この端末で交互に / 部屋をつくる / 合言葉で参加 の3つから選ぶ |
| ひとりで積む | 落とすまで何段積めるかに挑戦 |

### オンライン対戦

「2人で対戦」→「部屋をつくる」で 4 文字の合言葉が出ます。相手は「合言葉で参加」に
それを入力するだけでつながります。アカウント登録も自前サーバーも要りません。
合言葉の横の「コピー」ボタンでクリップボードに入ります（クリップボードが使えない環境では
合言葉が選択状態になるので、そのまま手動でコピーできます）。入力は小文字でも大丈夫です。

- 通信は **WebRTC の DataChannel**（P2P）。相手を探すシグナリングだけ
  [PeerJS の公開ブローカー](https://peerjs.com/)を借りています。
- **`https://` か `localhost` で開いたときだけ使えます。** WebRTC はセキュアコンテキスト限定なので、
  `http://192.168.x.x:5173/` のような LAN の生 IP では利用できません（ボタンが無効になり理由が表示されます）。
  離れた相手と遊ぶなら、下の GitHub Pages で `https://` 配信するのが手っ取り早いです。
- 相手が切断した場合はタイトルに戻り、理由が表示されます。

### ルール（どうぶつタワーバトル準拠）

- 交互に 1 体ずつウマ娘を落として、台座の上に積み上げます。
- **自分が落としたことが原因で誰かが芝生（地面）に落ちたら、落とした人の負け**です。
- 持ち時間は 1 手 30 秒。時間切れになるとその位置で自動的に落ちます。

### 操作

| | |
| --- | --- |
| ドラッグ（横） | 左右に動かす |
| ドラッグ（縦） | 回転させる |
| 指・マウスを離す | その場に落とす |
| ⟲ / ⟳ ボタン | 細かく回転 |
| おろす ボタン | 落とす |
| キーボード | ← → 移動 / ↑ ↓ 回転 / Space 落下 |

## 公開する（GitHub Pages）

`main` に push すると [.github/workflows/deploy.yml](.github/workflows/deploy.yml) が走り、
遊ぶのに必要なファイルだけを `_site/` に集めて GitHub Pages に配信します
（`tools/` や `.claude/` は配信しません）。

1. GitHub にリポジトリを作って push する
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
3. 以降は push するたびに自動でデプロイされる

公開先は `https://<ユーザー名>.github.io/<リポジトリ名>/` です。
参照はすべて相対パスなので、サブディレクトリ配信のままで動きます。

> **Pages に置くとオンライン対戦が使えるようになります。**
> WebRTC はセキュアコンテキスト限定なので、`https://` で配信される Pages が一番手軽です。

検索避けに [robots.txt](robots.txt) を置いてあります（`Disallow: /`）。

## ローカルで動かす

```bash
node tools/serve.mjs
```

<http://localhost:5173/> が開きます。ポートを変えたいときは `node tools/serve.mjs 8123` のように渡してください。

### index.html を直接開く場合

`file://` から開いても多くのブラウザ（Chrome / Firefox）では動作しますが、
ブラウザやセキュリティ設定によっては canvas の CORS 制限で画像のシルエット抽出に失敗します。
その場合はタイトル画面にエラーが表示されるので、上記のローカルサーバー経由で開いてください。
なお `file://` と LAN の生 IP ではオンライン対戦は使えません（`localhost` か `https://` が必要）。

いずれの方法でも、キャラクター画像は毎回 CDN から読み込むため**インターネット接続が必要**です。

### キャラクター一覧の更新

新キャラが追加されたら、公式サイトから取り直して [data/characters.js](data/characters.js) を作り直します。

```bash
node tools/fetch-characters.mjs
```

## 仕組み

### 画像の扱い

キャラクター一覧の各キャラクターの立ち絵（全身・**アルファ付き透過 PNG**・原寸 1125x1980 前後）を
imgix のパラメータ付き URL で参照しています。縦長なので幅ではなく高さを指定して縮小します。

```
https://images.microcms-assets.io/assets/.../specialweek_01.png?h=300&fm=png
```

171体すべてを毎回読むと重いので、1 ゲームにつきランダムな 30 体を選んで読み込みます
（12 体そろった時点でタイトルのボタンが押せるようになり、残りは遊びながら裏で読みます）。

この CDN は `Access-Control-Allow-Origin: *` を返すため、`crossOrigin="anonymous"` で読み込めば
canvas を汚さずにピクセルを読み出せます。そこで実行時に次の処理をしています
（[js/silhouette.js](js/silhouette.js)）。

1. アルファチャンネルから前景マスクを作る
   （白背景・透過なしの画像が来た場合は、外周から白を flood fill するフォールバックも用意）
2. 1px の膨張→収縮で細い毛先を繋ぎ、最大連結成分だけを残す
3. シルエットを Moore 近傍追跡して輪郭を取り出す
4. Ramer–Douglas–Peucker で 44 頂点以下に間引く

こうして得たポリゴンを `Matter.Bodies.fromVertices()` に渡し、poly-decomp で凸多角形に分解して
当たり判定にしています。髪・耳・しっぽ・広げた手足がそのまま引っかかりになるので、
どうぶつタワーバトルらしい「絶妙に噛み合う」挙動になります。

### オンライン対戦の同期方式

当たり判定は画像から実行時に生成しているため、ブラウザや環境によってポリゴンが数ピクセル
変わりえます。両者が別々に物理を回すと必ず食い違うので、**ホスト権威**にしました。

- **ホスト**（部屋をつくった側）だけが Matter.js を回し、全ウマ娘の座標と角度を 15Hz で送ります。
- **ゲスト**は届いた座標を補間して描くだけ。自分の手番の狙い（x と角度）だけをホストに送り、
  「落とす」もホストに依頼します。判定はすべてホストが行います。
- ただしゲストの持ちウマ娘は手元でも先に動かします（クライアント予測）。位置の計算式は
  ホストと同じものを使うので、遅延を感じずに狙いを定められます。
- 接続直後にホストが使うキャラ一覧を送り、ゲストがそれを読み込んでから対戦開始です。

### 画面サイズ

キャンバスは常にステージいっぱいに描画し、左右にレターボックスの余白を作りません。
「横幅いっぱい = ワールド幅 480」を基準にスケールを決め、縦に見える範囲は画面に合わせて伸縮します
（極端に縦が潰れる場合だけ、芝生が見える下限 520 に合わせて縮小）。
台座やウマ娘の大きさはワールド座標のままなので、画面サイズを変えても難易度は変わりません。

### ファイル構成

```
index.html                      画面
styles.css                      スタイル
data/characters.js              キャラクター名と公式立ち絵URLの一覧（171体・自動生成）
silhouette.js                   画像 → 透過スプライト + 当たり判定ポリゴン
net.js                          オンライン対戦 (PeerJS / WebRTC)
game.js                         ゲーム本体（物理・ターン進行・CPU・描画）
robots.txt                      検索避け
tools/fetch-characters.mjs      data/characters.js を公式サイトから生成
tools/serve.mjs                 動作確認用の簡易静的サーバー
.github/workflows/deploy.yml    GitHub Pages へのデプロイ
```

外部ライブラリは CDN から読み込みます。

- [matter-js](https://brm.io/matter-js/) 0.20.0 … 2D 物理エンジン
- [poly-decomp](https://github.com/schteppe/poly-decomp.js) 0.3.0 … 凹多角形の凸分解
- [PeerJS](https://peerjs.com/) 1.5.4 … WebRTC のシグナリングと DataChannel

### 物理パラメータについて

立ち絵は縦長で足元が細いため、素直な設定だと 1 手目から台座を転げ落ちてしまいます。
CPU 同士で自動対戦させながら調整し、重力 0.5・空気抵抗 0.06・摩擦 1.0（静止摩擦 3.0）・
台座幅 232px・ウマ娘の高さ 128px に落ち着きました。
また、回転させても塔のてっぺんからの隙間が一定になるよう、下端を基準に落下開始位置を決めています。
この設定で CPU 同士の自動対戦 10 戦の平均が 21 段（3〜56 段）でした。

### デバッグ

`index.html?debug` で開くと `window.UmaDebug` が生えて、`tick(dt)` で 1 フレームずつ手動で進めたり
`start(mode)` / `drop()` / `plan()` を直接呼んだりできます（自動対戦での調整用）。
